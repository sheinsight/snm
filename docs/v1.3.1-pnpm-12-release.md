# snm v1.3.1 pnpm 12 修复总结

## 修复问题

pnpm 12 的官方 Corepack 兼容入口会在首次运行时下载当前平台的 `@pnpm/exe.*` 原生包。此前 snm 在用户未设置 `COREPACK_NPM_REGISTRY` 时，把自身的 `npm_registry` 自动注入为 Corepack registry。企业镜像只同步 pnpm 主包、未同步平台包时，下载会错误地访问企业源并返回 404。

同时，`v1.3.0` 标签对应的 Rust crate manifest 仍保留 `1.2.8`，因此 `snm --version` 显示为 `1.2.8`。

## 架构调整

- pnpm 主包下载继续由 snm 的 `npm_registry` 控制。
- pnpm 12 平台原生包下载完全交给官方 `.mjs` 引导层。
- 用户显式设置的 `COREPACK_NPM_REGISTRY` 由子进程自然继承。
- 未设置 `COREPACK_NPM_REGISTRY` 时，官方引导层使用 `https://registry.npmjs.org`。
- 不提供企业源失败后自动回退公网的隐式策略；隔离网络应配置一个完整同步 `@pnpm/exe.*` 的专用 Corepack registry。
- 删除仅为错误 registry 映射增加的子进程环境覆盖接口，恢复单一执行路径。

## 版本调整

所有 snm 工作区发布 crate 和根 `Cargo.lock` 中的本地包版本统一升级为 `1.3.1`，确保 `snm --version`、构建产物和 Git 标签一致。

## 自动化验证

新增的 pnpm 12 E2E 会执行以下真实流程：

1. 从 npm 官方源取得固定版本 `pnpm@12.0.0` 主包，并通过本地服务模拟只同步主包的企业镜像。
2. 显式移除测试子进程中的 `COREPACK_NPM_REGISTRY`，确认 snm 不再把企业镜像映射给 pnpm 引导层。
3. 首次执行 `pnpm --version`，真实下载并校验当前平台的 `@pnpm/exe.*` 原生程序。
4. 确认输出版本为 `12.0.0`，并确认 `pnpm-native` 已写入 pnpm 包目录。
5. 设置 `COREPACK_ENABLE_NETWORK=0` 后再次执行，确认缓存可在无网络状态下复用。
6. 清理缓存并显式设置 `COREPACK_NPM_REGISTRY`，确认原生包请求严格发往用户指定源。

该测试不是忽略测试，会随 `cargo test` 和 `just ci-e2e` 一起执行。
